## 3. Done

- **1.1 Scaffold.** `uv` venv (Python 3.11), `pyproject.toml`, `Makefile` (`make help` lists every step). Weeks 2–4 targets are stubs.
- **1.2 Generator copied** from IndicFormBench (commit 6db4ae7f) into `datagen/generate/`, with every change marked `TinyScribe:`:
  - `render_flat()` returns pages in memory, with no PDF or PNG writes per instance.
  - ID numbers are `TEST-dddd`.
  - Train and test pages use disjoint handwriting samples (every 5th sample is test-only).
  - The template schema path now points into `datagen/`.
  - Templates: 30 JSON + 30 PDFs (22 copied, 8 synthetic regenerated byte-identical). Fonts: `assets/fonts/`.
- **1.3 Schemas.** 53 page schemas in `schemas/`, e.g. `eci_form7_hi_p0.schema.json`. Each holds fields (string, max length), checkboxes (boolean) and table rows (fixed length). All keys are required and no extras are allowed.
- **1.4 Builder** (`datagen/build.py`, recipe `datagen/split.yaml`).
  - Smoke run at 2% scale: 224 pages in 24 s on the Mac.
  - The split check passes: no test form type appears in train.
  - All 224 targets validate against their schemas. Free-text fields go up to ~360 characters, so their limit was raised to 400.
  - Full run: about 7,300 instances. On the Mac at 8 workers that is about 20 min; faster on the DGX.
- **1.5 Visual QA.** Bengali, Tamil and Hindi pages checked by eye:
  - Conjuncts are shaped correctly.
  - Comb boxes hold one akshara each.
  - Checkbox marks look right.
  - Heavy degradation is still legible.
  - `make qa` writes `data/qa.html` (50 pages next to their JSON) for your own pass once the full build exists.
- **1.6 Scorer.** `src/tinyscribe/normalize.py` and `score.py`. 33 tests pass (`make test`): Indic digits, date forms, spacing, zero-width characters, wrong/missing/hallucinated values, invalid JSON.
- **1.7 + 1.9 Client, prompt, eval runner.** Tested end to end on the Mac with llama.cpp (brew, commit `d8123504`) and Qwen3.5-2B Q4_K_M + F16 projector:
  - 4/4 pages returned valid JSON.
  - No thinking text in the output.
  - About 15 s/page, about 2.3k prompt tokens per page.
  - `make table` prints the README table.
- **llama.cpp pinned** to `d81235049384534c167caea52b85a694f6103d14` (`third_party/LLAMA_CPP_COMMIT`). The Mac test ran on this exact commit.
- **DGX scripts written:** `scripts/dgx/setup_env.sh`, `scripts/build_llamacpp.sh`, `scripts/dgx/download_models.sh`, `quant/convert.sh`, `scripts/serve_pool.sh`.
- **Plan v5** written with the decisions above as notes (v4 kept word for word).

**DGX (run by Claude over SSH, every job in tmux session `ts`, logs in `~/tinyscribe/runs/logs/`):**

- **1.8 Setup.**
  - Python venv, with Pillow's raqm shaping engine working.
  - CUDA 12.6 `nvcc` from micromamba, at `~/indicformbench/tools/bin/micromamba`.
  - Handwriting banks linked from IndicFormBench.
  - Qwen3.5-9B (19 GB) and 2B (4.3 GB) downloaded.
- **llama.cpp CUDA build.**
  - The first build failed at link time: `libcudart.so.12` was not found, because it lives in the micromamba env.
  - Fixed by building ggml statically and adding an rpath to `.cuda/lib`. The failed build is kept in `runs/llama_build_failed_1`.
- **1.4 Full dataset:**
  - 6,973 instances, 64 workers, 6.2 GB.
  - Train: 10,010 pages (EN 2508, HI 2500, BN 2500, TA 2502). Test: 401 pages (100/100/100/101).
  - 2,588 handwritten pages and 800 calibration pages.
  - One instance had a truncated value (`eci_form6a_hi_s3010008`, free text); its ground truth holds only what was drawn.
  - A handwritten Hindi test page checked by eye: real IIIT words and EMNIST digits.
- **Job launcher bug.** `scripts/dgx/tjob.sh` first lost the quoting of arguments with spaces, so one job died silently. It now writes each job as a script with `printf %q`.
- **GPU 4** was taken by another user during the run, so the baselines used GPUs 5–7.
- **1.10 Zero-shot 9B baseline**, all 401 test pages through llama.cpp with grammar on:

| Model | Size | Field F1 | English | Hindi | Tamil | Bengali | Valid JSON |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 9B zero-shot, BF16 (DGX) | 18.41 GB | 37.0 | 44.5 | 30.7 | 31.4 | 39.8 | 100.0 |

- Checkbox accuracy 89.5%. Median 11.3 s and ~495 output tokens per page on one A100. No request errors.
- About as many invented values (FP 5,442) as correct ones (TP 3,044). Values land in the wrong key, and letters in comb fields come out spaced. This is the gap fine-tuning has to close.

**First numbers (smoke only, 4 test pages, not a result):** Qwen3.5-2B Q4_K_M zero-shot scored field F1 44.8 with 100% valid JSON. Two things already show up:

- The model spaces out letters in box-per-letter fields ("P r i y a").
- Pretty-printed JSON costs extra tokens.

Fine-tuning on compact targets should fix both.
